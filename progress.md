### Security Model

The installation follows a **TWO-PHASE** security model:

| Phase | User | Purpose | Requirement |
|-------|------|---------|-------------|
| Phase 1 | root | System hardening, SSH config, new user creation | **REBOOT REQUIRED** |
| Phase 2 | new user | Ethereum client installation | Run after reboot |

This separation ensures:
- Security changes are properly applied before client installation
- User verifies SSH access works with new credentials before proceeding
- Clean separation between privileged and non-privileged operations

## Implementation Details

### install.sh
- Root check and prerequisites verification
- Git clone/update repository
- Automatic handover to configuration wizard
- Supports `--vibe` flag for non-interactive mode
- Explains two-phase installation process

### configure.sh
- Whiptail-based interactive menus
- Network selection (mainnet/holesky)
- Hardware profile detection
- Client recommendations based on hardware
- MEV solution selection
- Fee recipient and graffiti configuration
- Generates TWO phase scripts:
  - `install_phase1.sh` - System hardening (run as root)
  - `install_phase2.sh` - Client installation (run as new user)
- Supports `--vibe` flag for sensible defaults

### run_manifest.sh
- Auto-detects which phase to run based on user context
- Executes appropriate phase with logging
- Error handling with rollback hints
- Progress tracking with colored output
- Dry-run mode support
- Supports `--phase1` and `--phase2` flags

### doctor.sh
- System requirements verification
- Service health checks
- Configuration validation
- Network connectivity tests
- Port availability checks (with fallback for missing `ss`)
- JWT secret verification
