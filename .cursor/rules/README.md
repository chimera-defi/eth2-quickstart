# Agent Rules: Use `docs/` for Context

- Always consult the documentation in `docs/` before making decisions or edits.
- Prefer citing relevant sections from files in `docs/` to enrich context.
- Keep `README.md` in the repo root as the single entrypoint for users; deep docs live in `docs/`.
- When generating or moving new Markdown files, place them under `docs/` unless explicitly told otherwise.
- Follow project standards: clear naming, high-verbosity code, early returns, robust error handling, and no inline comments except where essential for comprehension.
- Update or add to docs when changing behavior, interfaces, or workflows.

Shortcuts:
- Configuration guide: `docs/CONFIGURATION_GUIDE.md`
- Workflow: `docs/WORKFLOW.md`
- Scripts overview: `docs/SCRIPTS.md`
- Glossary: `docs/GLOSSARY.md`
